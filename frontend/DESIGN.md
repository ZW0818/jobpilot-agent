# JobPilot 界面设计规范

## 使用场景与方向

JobPilot 是用来完成任务的求职工作区，采用应用界面规范。用户首先要解决的问题是：这份简历与目标岗位有哪些可验证的匹配、还有哪些证据需要补充？

本次由方向脚本提供 Achromatic ledger 与 Editorial greeting 两种候选，选择 **Achromatic ledger**（seed `20261104`）。原因是本产品以证据核对、分项评分和报告阅读为主，数字与内容应先于装饰。保留中文系统字体，采用低饱和蓝灰底色、白色内容面和中性导航，评分进度使用一套蓝色。没有重抽方向。

产品特征是“岗位要求 → 简历证据 → 行动建议”的对照链，以及“已匹配 / 部分覆盖 / 未找到证据”的判断方式。首页让用户先添加材料，结果旁同时保留依据；不制作虚假统计、模拟评分或默认演示数据。

## 布局与排版

- 桌面为 64px 图标导航轨，内容最大宽 1240px；主工作台为弹性材料列、12px 间距、344px 结果列。两侧页边距相同，所有模块共用对齐线。
- 三个工作视图分别为岗位匹配、分析报告、求职问答；切换视图保留当前材料、分析结果与对话。
- 标题 24px，手机 22px；面板标题 16px，正文 14px，数据与标签 13–14px，12px 留给时间、来源及辅助说明。
- 使用本机中文系统字体；数字统一启用 tabular-nums，数值列右对齐。未知数值用短横线，有结果且为零时显示真实零。
- 面板半径 8px、控件半径 6px；面板只用轻边框或底色区分，不堆叠阴影。
- 手机导航改为底部短标签栏，留出对应底部空间；材料和结果按阅读顺序排列。平板有独立断点，不能将表格、标签压缩到不可读。

## 颜色与组件

- 画布 `#f2f4f7`，内容面白色，主文字 `#16191d`，次级文字 `#5e646c`，面板边框 `#e6e8eb`。
- 主操作近黑色 `#202429`；数据蓝 `#1d5fbf` 只用于评分和焦点。状态只使用必要的浅色与深色文字组合。
- 禁止背景渐变、玻璃面板、发光边框、静止卡片的大阴影、无意义图标色块和伪 KPI。
- 不放宣传页式大标题、装饰性流程编号、悬浮胶囊导航、广告性功能卡片。
- 导航项、面板标题和操作均使用真实业务词，不添加无功能的搜索、头像、铃铛或分享按钮。

## 状态与交互

- 首次使用显示真实空态和下一步操作；评分位置同时说明证据判断方法。
- 正在刷新时保留上次结果，明确标注更新中；执行记录随接口返回，不模拟实时进度。
- 错误靠近发生错误的输入与操作，保留材料并可重试。
- 文件类型说明与隐私用途说明可见，简历会发送到配置的模型服务，不能声称只在本地处理。
- 报告支持 Markdown 表格、来源展开和下载。标签页支持方向键、Home/End；所有控件可用键盘访问并具有可见焦点。
- 动效仅用于操作反馈，不做入场表演；支持 prefers-reduced-motion。
- API Key 留在后端环境，不进入前端源码、截图、日志或浏览器存储。

## 交付检查

在 1440px、768px、390px 下检查生产构建，查看实际截图，核对空态、输入就绪、加载、结果、错误、导航、表格与键盘操作。页面不得横向溢出；表格和代码可在自己的容器内滚动。

本次改造前的 Taste Skill 浏览器基线为 7 FAIL、9 WARN；截图和检查报告保存在本机忽略目录 `.taste-skill/`。设计脚本无需全局安装；后续维护以本规范和上游 App screens 为准，不将营销页的照片或动画数量要求套到工作区。

### 验证记录（2026-11-04）

- 生产构建在 1440 / 768 / 390px 的最终检查为 **0 FAIL、0 WARN**，没有放行规则；首屏标题分别为 24 / 24 / 22px。
- 已查看三个宽度的首屏和整页截图。三轮复核依次处理：营销页装饰与信息层次、次级文字与面板节奏、手机按钮和表格及首次问答的空白区。
- 浏览器完成 27 项交互检查，包含首次使用、文件选择、示例 JD、重复提交限制、真实分析、报告标签方向键、Markdown 表格与下载、视图保留、三种宽度的溢出检查，以及模拟网络错误后的重试。
- 首轮使用脚本内的虚构简历实际请求后端，确认画像和辅导均为 `model/success`、检索为 `hybrid`。最后的展示层复核重放该真实响应，避免重复调用模型；测试结果没有植入默认页面。
- 视觉复核的七个结论：主任务先于说明；模块共享边界；颜色用于评分而非装饰；总分等于四项之和；未知与零分可区分；每条进度有满分标尺；手机导航折叠且报告表格在自身容器内滚动。
- 保留的限制：完整 Markdown 报告较长，手机上需要纵向阅读，四列表格需要横向查看；另有“匹配证据”视图按手机列表呈现，便于逐条核对。
