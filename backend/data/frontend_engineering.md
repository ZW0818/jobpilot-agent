# 前端组件、交互质量与面试

## React 组件划分与状态管理
React 组件可按界面职责拆分，先确定最小必要状态，再从已有数据计算派生值；共享状态应放在需要它的组件共同父级。面试问题：为什么不把筛选后的列表重复存到 state？组件之间共享状态如何选择归属？
项目证据建议：展示组件边界、数据流、状态设计和真实交互，说明 React 或 Vue 技术选择的背景。

## 异步请求与页面状态
页面要覆盖等待、加载、成功、空结果与失败状态，防止重复提交和过期请求覆盖新结果。面试问题：连续切换筛选条件时如何避免旧响应覆盖新数据？用户重新提交后是否还应该显示上一次成功的流程状态？
项目证据建议：展示请求失败、慢响应和重复点击的处理，以及接口联调时约定的数据结构。

## 表单可访问性
表单输入需要可识别的标签。HTML label 的 for 应与输入 id 对应；React 使用 htmlFor。占位文字不能替代稳定的字段标签。面试问题：自定义上传组件如何让键盘和辅助技术识别？错误提示如何与输入关联？
项目证据建议：演示键盘操作、焦点反馈、label 关联和错误提示，避免仅用颜色传达结果。

## 前端项目简历与性能证据
前端简历建议说明 React、Vue、TypeScript、构建工具在实际功能中的用途，按组件设计、数据流、接口交互和用户体验组织项目内容。性能优化必须先测量再改动。面试问题：你如何证明一次页面优化有效？如何区分网络请求慢和组件渲染慢？
项目证据建议：使用同一设备、网络与数据规模对照耗时，写清测试方法；没有测量时使用“完成组件拆分”等可核验表述。
