# 后端工程、性能排查与面试

## MySQL 慢查询与索引排查
慢查询排查先确认 SQL、参数、数据规模和耗时分布，再使用 EXPLAIN 查看执行计划中的访问路径、索引和估算行数。EXPLAIN ANALYZE 会实际执行语句并提供运行信息，使用时要明确影响。面试问题：为什么有索引仍然可能扫描大量数据？如何证明一次 SQL 优化有效？
项目证据建议：记录优化前后执行计划、扫描行数和相同压测条件下的延迟，不编造吞吐量和收益。

## Redis 缓存一致性与热点
Cache Aside 读请求先查 Redis，未命中再读主库并回填；主库更新后让缓存失效，TTL 用于限制缓存陈旧时间。热点过期可能触发并发回源，需要考虑请求合并、互斥回填或过期时间分散。面试问题：缓存命中率很高时为什么仍可能出现数据库尖峰？如何处理更新与回填交错导致的旧值？
项目证据建议：说明一致性要求、失效策略、热点键、回源量及 Redis 故障时的行为；不能把缓存方案描述成天然强一致。

## FastAPI 同步调用与并发
在 FastAPI 的 async def 路由内直接运行同步模型、文件解析或数据库调用，会占用事件循环。阻塞操作应放在线程池或使用真正的异步客户端；普通 def 路由由框架在线程池执行。面试问题：为什么写了 async 接口仍被慢请求阻塞？如何测试慢分析期间健康检查的响应情况？
项目证据建议：说明 I/O 与计算任务的边界，展示并发测试、超时策略和连接池配置。

## API 契约与故障定位
后端项目描述建议写清输入校验、接口契约、异常响应、日志及部署方式。接口失败时先复现具体请求，再区分参数、应用、数据库与外部依赖问题。面试问题：如何设计接口幂等性和错误响应？怎样关联一次请求经过的多个处理节点？
项目证据建议：提供 API 文档、可复现的测试用例和脱敏日志；说明个人负责的模块及边界。
